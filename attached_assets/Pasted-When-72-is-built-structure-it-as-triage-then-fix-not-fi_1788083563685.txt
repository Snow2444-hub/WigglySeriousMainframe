Recommended implementation shape

I agree with avoiding nine unrelated patches.

The next implementation should first design one shared authoritative data scope/provenance boundary, then apply it to the five Priority 1 tables.

The mechanism should provide:

    A production/authoritative scope that production readers require.
    A test scope that cannot satisfy production-reader predicates.
    Automatic assignment at the persistence boundary rather than relying on each test author to remember a namespace.
    A shared reader predicate/helper so new operational readers cannot silently omit the boundary.
    A root authority for ingestion-derived rows, with child tables inheriting or joining to that authority.
    A migration/backfill rule for existing rows.
    Failure-before-teardown tests proving leaked test rows remain invisible.

One design constraint is important: drugs and pbs_items are master/reference tables, while predicted_reductions, schedule_changes, and ingestion_runs are operational/derived tables. They may share one scope contract, but the authority relationship may differ:

    Master rows need an explicit data scope.
    Derived rows should ideally also reference a scoped authoritative ingestion run or source.
    ingestion_runs becomes the authority root rather than depending on another table.

No code changes should be made until that shared boundary is selected and its behavior against existing endpoint tests is understood.
