Four changes to the Upcoming Changes / PBS updates views. Items 1-3 are display;
item 4 is a navigation bug.

=== 1. SORT: NEAR-TERM BY AMOUNT, FAR-FUTURE PUSHED DOWN ===
Currently the list mixes horizons badly — e.g. a Vyvanse 26% reduction dated
1 Apr 2031 sits near big imminent reductions, even though it's 5 years away and
not actionable.
Change the default ordering to:
  a. Split events at a near-term horizon (default 12 months from today).
  b. Within the near-term group: sort by reduction AMOUNT, largest first.
  c. Everything beyond the horizon sorts AFTER all near-term events, regardless
     of how big it is (so a huge far-future reduction still ranks below small
     imminent ones). Within the far-future group, sort by soonest date.
The goal: big + soon rises to the top; big + distant (Vyvanse 2031) sinks to the
bottom. Confirm the Vyvanse 2031 event ends up below the 1 Oct 2026 events after
this change.

=== 2. FILTER: TIME SCOPING INCLUDING A YEAR SELECTOR ===
Add filtering by time period so the user can scope the list — e.g. choose 2026
and see only that year's events. Include:
  - A quick year selector (e.g. 2026, 2027, ...) driven by the actual event
    dates present, not a hardcoded list.
  - Keep the existing From/To date pickers working alongside it.
When a year/period is selected, the sort from item 1 applies within that scope.
Report how the year options are generated.

=== 3. COLUMN HEADERS / EXPLAIN THE CONFIDENCE LABELS ===
The list shows labels like "HIGH" / "MEDIUM" with no column header or legend
explaining what they mean (confidence in the prediction, not size of change).
Add a header or label so it's clear what the column is (e.g. "Confidence") and,
ideally, a short tooltip or legend describing what HIGH / MEDIUM / LOW mean.
Do NOT change the values themselves — just make the column self-explanatory.

=== 4. NAVIGATION BUG: BACK GOES TO THE WRONG PAGE ===
Reproduction: on a drug (e.g. Relaban), expanding shows its two PBS lines.
Clicking a line navigates to the drug overview. Pressing Back then lands on the
PBS DIRECTORY, not the page the user was actually just on.
- Trace the navigation: the Back action should return to the previous page in
  history (the expanded drug view the user came from), not redirect to the PBS
  directory.
- This is likely a hardcoded/default back-target or a routing push that replaces
  history instead of pushing onto it. Find which and fix it so Back returns to
  the actual previous view.
- Report the cause (hardcoded back link vs history.replace vs missing route
  state) and confirm the back path now returns to the originating page from both
  entry points (from the PBS directory AND from an expanded drug line).
